# JADE production reproducibility note

## Scope

This project treats the Electricity Authority's published JADE inputs and outputs as authoritative evidence. It also aims to reproduce selected JADE counterfactuals where the public model and public input data permit that.

During development of the +1 GWh renewable impulse-response experiment, we found a reproducibility mismatch between the latest public JADE source code and the Authority's published Week 52 2025 input bundle.

## Reproduction attempt

The experiment uses the latest published Week 52 2025 JADE input set as the baseline and changes only one item: an additional 1 GWh of fixed renewable generation in a selected future week. Before introducing that perturbation, the baseline case itself must load successfully in the same model code.

Using the public `EPOC-NZ/JADE.jl` main branch (reported by Julia as JADE v1.1.0), the baseline Week 52 2025 data fail while loading reservoir constraints with:

```text
The maximum contingent storage is not constant for reservoir LAKE_PUKAKI.
```

The failure occurs inside `initialisereservoirs()` while reading `reservoir_limits.csv`.

## Why this matters

The public JADE implementation explicitly calculates the total contingent-storage tranche for every reservoir and every week. It then requires that the maximum contingent storage be constant through time; otherwise it raises the error above.

The Authority's published Week 52 2025 input bundle contains time-varying contingent-storage limits for Lake Pukaki, yet the Authority also publishes successful JADE outputs from that same weekly model cycle.

That means at least one of the following is true:

1. the Electricity Authority production run used a JADE revision that differs from the currently public `main` branch;
2. the production process applies preprocessing to the reservoir-limit data before JADE loads them;
3. the production environment contains a local patch or configuration not represented in the public repository; or
4. another undocumented step reconciles the time-varying Pukaki contingent-storage limits with the model requirement.

We do not currently have enough evidence to distinguish between these possibilities.

## What we are not doing

We are not modifying the published Lake Pukaki limits simply to make the public code run. Doing that would make the counterfactual easier to execute but would no longer reproduce the Authority's published model assumptions.

We are also not treating the failed public-code run as evidence that the Authority's published JADE outputs are invalid. The published outputs demonstrate that the Authority has a working production process; the issue here is whether that process is fully reproducible from the currently public code and data.

## Precise question for EA / EPOC

> Which JADE commit, tag or production build was used to produce the Electricity Authority's Week 52 2025 Expected Water Values / JADE dataset (input timestamp approximately 25 December 2025), and does that production build contain different handling of time-varying contingent storage for Lake Pukaki? If the public `EPOC-NZ/JADE.jl` repository is intended to reproduce that run, is there a preprocessing step or additional file required before loading `reservoir_limits.csv`?

A commit SHA is the most useful answer because it would allow the experiment workflow to pin the exact model version.

## Impact on the renewable impulse-response experiment

The experimental design itself remains valid:

- baseline and +1 GWh pulse cases use identical demand, inflows, outages, reservoir starting levels and simulation paths;
- the pulse is inserted through JADE's fixed-generation input;
- paired outputs measure additional stored hydro energy, hydro dispatch changes, spill and thermal displacement through subsequent weeks;
- raw Authority inputs remain temporary and only derived paired differences are retained.

The workflow is paused at model loading until the production/public-code compatibility question is resolved.

## Interim use of JADE data

This limitation does not prevent use of the Authority's already-published JADE outputs. Those outputs remain the preferred source for current-system seasonal hydro-storage distributions, thermal dispatch requirements and shortage indicators in this project.

Until the production build can be reproduced, any new counterfactual JADE result generated by this repository should be clearly separated from the Authority's published model outputs and should not be presented as an EA result.
